What Is Quarto, Actually?

The Core Idea

Quarto is a publishing system that mixes writing and code in one document.

  • You write in Markdown (plain text with light formatting)
  • You embed R code in chunks
  • Quarto runs the code and weaves the output — tables, plots, results — directly into the final document
  • It can render that document as a webpage, a PDF, a slide deck, or a Word file

Its role in this class: every .qmd file you write becomes a page of your portfolio website. Quarto is the tool that turns your analysis into something you can show an employer.

Quarto vs. a Hand-Coded Website

“How is a Quarto website different from a hand-coded HTML, CSS, and JavaScript website?”

Hand-coded site: you write HTML structure, CSS styling, and JavaScript behavior yourself, file by file.

Quarto site: you write content and analysis in .qmd files. Quarto generates the HTML, CSS, and navigation for you, based on a config file (_quarto.yml) that controls the whole site’s structure and look.

Trade-off: you give up some low-level control, and gain the ability to focus on analysis instead of web development.

Markdown vs. R Code Chunks

“When do I need to use an R code chunk, and when is regular Markdown enough?”

Use plain Markdown when: you’re writing explanation, interpretation, headers, or narrative text — no computation involved.

Use an R code chunk when: you need R to actually do something — load data, run a calculation, make a plot, print a table.

Rule of thumb: if you need the computer to compute it, it’s a chunk. If you’re just explaining it, it’s Markdown.

File Management, Again

Where Do New .qmd Files Go?

“I am still not sure how to add more .qmd files to the repo in the correct folder.”

  • Every new .qmd file lives inside your portfolio repo folder, in the location your site structure expects (we’ll point at the exact folder together, live)
  • Create it with GitHub Desktop tracking the same local folder — never create it somewhere else and move it later
  • If a file isn’t inside the repo folder your project is tracking, Git doesn’t know it exists

What Does “Render” Actually Do?

“If I press render, does that render all qmd files in the repo, or just the one I have open?”

Rendering one file renders just that file — it re-runs its code and regenerates its output page.

Rendering the whole site (quarto render at the project level) rebuilds every page and the navigation between them.

The Absolute Basics

Reading Code Syntax

“What does the # mean or the >?”

Good question — nobody should feel silly asking this.

  • # — a comment. R ignores it. Used to leave notes for yourself or others in the code.
  • ##, ### — in Markdown text (not code), these create headers of different sizes
  • > — the prompt in your R Console, showing R is ready for a new command. You don’t type it yourself
  • %>% or |> — the “pipe.” Takes the result of one step and feeds it into the next. You’ll use this constantly

We will keep naming these out loud as they come up, not just assuming they’re obvious.

How to Prepare Between Classes

“How can I better prepare for each class?”

  • Re-run (re-type is even better) the code from lab yourself, from a blank script, without copy-pasting
  • If something breaks, sit with the error message for a few minutes before searching or asking

  • Small, consistent repetition beats a single long cram session - Use AI to help explain code chunk and get you ‘un-stuck’
